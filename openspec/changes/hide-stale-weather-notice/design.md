# Design

## Context

動機見 [proposal.md](proposal.md)。本分支以 `e17f867777d7a6d2037157fe3363c20132d85536` 為基準，與 Claude 正在處理的 `centralize-builtin-config` 工作區分離。

目前 `dataState.mjs` 會依門檻超時、新回應不涵蓋當下、或既有資料涵蓋耗盡而保留 `stale` 狀態；`useWeatherStation.js` 的 `advisory` 直接使用優先異常種類決定文字與樣式。現有優先順序為 never > stale > unlocated，因此只刪除 stale 文案會留下空警告或遮住同時存在的定位異常。

本機於 2026-11-01 11:51 查詢內湖區時成功取得從 12:00 開始的預報；同一份資料以 12:00 為判定時間即可通過涵蓋檢查。這是可重現的條件，不足以證明 Pi 12:02 仍提示的完整根因，故本次不改資料判定。

## Goals / Non-Goals

**Goals:**

- 用共用呈現政策暫時排除 stale 警告，讓兩個版面與睡眠模式套用相同規則。
- 保留內部狀態、資料與成功時間，讓後續調查仍有依據。
- 把資料無法取得及定位未知保留為可見異常，避免一起被遮蔽。

**Non-Goals:**

- 不處理 CWA 批次交接、時段合併、API 請求或重試策略，不改目前的成功條件與門檻。
- 不新增外部設定、開關、提示區、按鈕或診斷畫面。
- 不修改 Electron main process、API key 處理、設定集中化或部署機制。

## Decisions

### D1：保留資料異常，在呈現前選出可見異常

`resolveAnomaly` 與其 `kind`／`all` 結果保持原意。提示選擇以全部異常為輸入，只讓 never 與 unlocated 產生可見警告，優先順序維持 never 在 unlocated 之前；stale 留在內部。這使 stale + unlocated 仍能顯示定位未知。

不採用將 stale 判為正常、重設 `lastSuccessAt` 或清除過期原因的作法，因為那些會掩蓋資料狀態。也不只把過期文字改成空字串，因為文字、警告樣式及其他異常的優先選擇必須一起正確。

### D2：在共用 advisory 路徑處理，沿用既有一般訊息

主要變更位於 `src/composables/useWeatherStation.js` 的共用提示選擇。沒有可見異常時，使用既有外出建議，缺少建議時使用既有預設訊息；`kind` 為一般提示，避免留下警告配色。兩個版面沿用共用輸出，不各自加入例外。

當仍有可見異常時，文字與睡眠模式樣式沿用現行規則。抑制過期提示本身不觸發新的天氣或 AI 請求，也不改 Codex 既有的最後成功更新時間標示。

### D3：同步開發異常範例並維持行為測試

`devFixtures.mjs` 的過期長文字與 station 整合測試仍引用該訊息。開發異常預覽改用仍允許呈現的異常內容，維持長文字截斷驗證；正式版的 DEV 閘門保持不變。

行為變更採 test-first：新增 stale-only 顯示一般提示、三種 stale 成因一致隱藏、stale + unlocated 顯示定位警告的整合測試。資料有效性測試繼續斷言 stale 仍存在；不能刪除這些斷言來製造通過結果。

### D4：暫時措施與設定集中化各自追蹤

本 change 只改訊息選擇與文件，`centralize-builtin-config` 的常數來源、fallback 與測試注入介面不在本次範圍。兩者都可能修改 `useWeatherStation.js`；整合前對照實際版本，保留設定集中化的結果，不恢復舊的門檻字面值。兩份 `time-station` delta 修改不同 requirement，仍須在整合後重新驗證。

## Risks / Trade-offs

- 隱藏過期警告後，使用者較難察覺天氣資料可能偏舊。依本次明確要求暫時接受此呈現取捨；保留既有資料更新時間與內部狀態，不將資料標為新鮮。
- 只檢查最高優先異常會漏掉同時存在的定位問題。呈現選擇必須檢查全部異常，並以整合測試覆蓋組合情境。
- 開發測試可能把舊文案重新帶回畫面。同步 fixture 與其文字斷言，並驗證兩個版面。
- 本次沒有根因修復，未承諾天氣資料因此恢復更新。文件與驗收均須區分「提示隱藏」與「資料更新正常」。

## Migration Plan

不遷移或清除使用者設定、localStorage 或天氣資料。實作經設計 review、測試與 Electron 驗證後，使用既有 AppImage 建置及安裝流程部署；本次規劃建立不等於已部署。回退時還原提示呈現的實作與文件，不需要回退設定集中化或重設使用者資料。

## Open Questions

- 後續如何區分擷取成功時間、官方批次發布時間與預報有效時段，需另行確認；不影響本次單純隱藏提示的範圍。
- 過期提示何時恢復、以何種條件呈現，待使用者完成調查後另立變更；本次不設自動恢復日期。
